# Онлайн-проверка Freedom CQA

Рабочая страница: https://freedom-bank-concept.vercel.app/check.html.

1. Войди в аккаунт менеджера. Сотрудники видят своё рабочее пространство и апелляции; права на профили остаются под контролем Supabase RLS.
2. Прикрепи JSON с диалогами. В режиме «Авто» отдельные записи JSON сохраняются отдельно. Для частей одного разговора выбери «Один чат»; режим «Набор диалогов» запрещает объединение независимых записей.
3. Открой набор и нажми «Оценить участников» (или «Оценить весь файл» внутри карточки). Каждый диалог получает отдельные карточки бота и оператора, если оба присутствуют. У каждой карточки восемь критериев, обоснования и ссылки на реплики. Оценка бота не попадает в рейтинг сотрудника.
4. Открой критерий и подай апелляцию с конкретным аргументом. Для оценки ИИ запускается повторное рассмотрение; исходное решение сохраняется. Ручные решения пересматривает проверяющий. Решение ИИ после апелляции остаётся предварительным и не становится обучающим эталоном автоматически.
5. Скачай результаты файла или сохрани оценку оператора в профиль сотрудника. История рабочего пространства сохраняется в этом браузере; публикация в профиль сотрудника выполняется отдельно. Для получения готовой автооценки можно повторно загрузить тот же файл: идентификаторы реплик и запросы стабильны.

## Как выполняется оценка

Vercel обслуживает интерфейс, проверяет вход через Supabase и хранит задачи в закрытом Vercel Blob. Модель qwen3.5:4b работает на ПК через Ollama. Программа на ПК сама обращается к очереди по HTTPS; открывать порты ПК в интернет не требуется.

На этом компьютере движок расположен в соседней папке `../cqa-checker`. Запуск: `start-cloud-worker.ps1`. Скрипт запускает модель и обработчик в фоне. Повторный запуск просит уже работающий обработчик немедленно проверить очередь. Внешние ключи и содержимое диалогов не выводятся в командную строку. Секрет обработчика хранится только в игнорируемом `.env.worker.local` и защищённой переменной Vercel; его нет в браузерных файлах.

ПК должен быть включён, подключён к интернету и не находиться в спящем режиме. При выключенном ПК задачи ожидают обработки. Проверка новых задач в простое происходит раз в десять минут; после начала обработки следующие задачи берутся сразу. Длительность оценки зависит от размера диалога и нагрузки на ПК. Остановка ожидания в браузере сохраняет уже полученные оценки и не уничтожает серверную задачу.

Работает исходный чек-лист Freedom Broker: согласованные веса 5/20/10/30/15/15/5, восьмой критерий — отдельный флаг. N/A исключается с нормализацией оставшихся весов до 100. Консультация: 0/5/10/15/20; управление диалогом: 0/4/7/10. Для бота фактически завершённая передача оператору считается полноценным завершением. Изменённые определения и веса доступны для ручной проверки; сервер отклоняет их для автооценки, чтобы не выдавать результат по другому чек-листу.

## Хранение и границы

Каждая задача принадлежит пользователю, который её отправил. Другой пользователь не может получить её по ID. В очереди хранятся компактные записи; полные транскрипты и результаты лежат в отдельных закрытых объектах. Индекс завершённых задач очищается от записей старше семи дней при следующих изменениях очереди; объекты Blob автоматически не удаляются. Для постоянной рабочей истории используй профили сотрудников и экспорт. Одновременное изменение индекса защищено ETag; потерянное подтверждение захвата задачи восстанавливается с той же арендой.

Автопроверка принимает до 1000 реплик и 60000 символов на диалог, до 200 оценок участников на пользователя в сутки, до 50 ожидающих задач в общей очереди. Контролируется месячный лимит операций записи. На Hobby действуют также общие бесплатные лимиты Vercel Blob: https://vercel.com/docs/vercel-blob/usage-and-pricing. При исчерпании квоты проверка сообщает об ошибке; платный тариф автоматически не подключается. Аудио можно прослушивать; для оценки нужен готовый транскрипт, распознавание речи пока не подключено.

Оценки модели предварительные. ИИ извлекает факты, код проверяет доказательства и рассчитывает баллы. Два прохода одной модели не являются независимыми экспертами. Без подтверждённой базы знаний нельзя гарантировать правильность внутренних тарифов, финансовых сроков и процедур.

## Проверки кода

`npm ci`, `npm run build`, `npm test`, `npm run check`.

В `npm test` включены проверки импорта, ролей, рейтингов, приглашений, кабинета сотрудника, очереди, принадлежности задач, восстановления аренды, апелляций и 130 последовательных оценок с отдельным хранением полных данных. Тесты сайта используют синтетические ответы; реальные вызовы локальной модели проверяются отдельно в лаборатории CQA.

`npm run dev` запускает статический сайт. Облачный API предназначен для Vercel; для полностью локальной проверки используй отдельный сайт из `../freedom-bank-integrated` и Python-сервис `../cqa-checker`.

Сохранён также альтернативный `npm run dev:model`: он обращается к отдельному llama-server на порту 8080 через `/api/cqa/analyze`. Этот адаптер использует исходную инструкцию обучения для оператора. Интерфейс запрещает выдавать его результат за оценку бота. Автоматический пересмотр через очередь и лабораторные метрики в этом проекте относятся к основному Python-проверяющему; качество отдельного файла дообученных весов через этот адаптер здесь не измерялось.

## Веса от 8 ноября 2026

Контакт 5, потребность 20, идентификация 10, консультация 30, эмпатия 15, управление 15, завершение 5. Всего 100. Консультация даёт 0/7,5/15/22,5/30 баллов; управление — 0/6/10,5/15. Для совместимости фактические уровни модели остаются 0/5/10/15/20 и 0/4/7/10, а вклад в итог пересчитывается пропорционально; интерфейс сохраняет исходные шкалы /20 и /10. Это изменение расчёта, а не обучение весов языковой модели.

Рабочие наборы со стандартным старым чек-листом переходят на новые веса с уведомлением. Произвольные чек-листы не мигрируют. Опубликованные оценки в профилях и прежние отчёты сохраняют исходный чек-лист. Серверная задача содержит снимок версии весов, поэтому новые проверки не используют старый кэш. Ранее поставленные задачи и апелляции сохраняют свои веса.

## Распознавание аудио и рентген разговора

Кнопка «Получить транскрипт» у загруженной записи звонка отправляет файл в OpenAI (`gpt-4o-transcribe-diarize`): речь распознаётся с разделением на голоса и таймингами. Оператор определяется по его фразам («Freedom Broker», «меня зовут», «менің атым», «my name is», запрос кодового слова); если признаков нет, роли голосам назначает проверяющий в «Рентгене разговора».

- На сайте файл до 25 МБ загружается напрямую в закрытый Vercel Blob, функция `api/transcribe.mjs` распознаёт его и сразу удаляет. Доступно только проверяющим.
- Включается переменной окружения Vercel `OPENAI_API_KEY` (Settings → Environment Variables), после чего нужен повторный деплой. Без ключа кнопка сообщает, что распознавание не настроено.
- Расходы ограничивайте лимитом в настройках проекта OpenAI (Limits → monthly budget).
- Локально: `OPENAI_API_KEY=... npm run dev` — файл отправляется напрямую, без Blob.

«Рентген разговора» показывает ленту реплик оператора и клиента по времени, долю речи, среднее время ответа оператора, самую долгую паузу, перебивания и места, где чек-лист нашёл замечания. Вкладка «Оператор / клиент» показывает реплики каждой стороны отдельно с таймингами. Клик по реплике переходит к этому месту записи.
