# Полный локальный проект CQA

В репозитории теперь находятся сайт, Python-проверяющий, локальная страница проверки, история апелляций, синтетическая память и скрипты формата результатов. Бинарные модели и клиентские данные остаются на компьютере.

## Запуск на Windows

Нужны Node.js 22+ с npm, Python 3.12 и Ollama. На компьютере с Codex можно использовать встроенный Python. Для другого пути задай `CQA_PYTHON`.

1. Склонируй репозиторий и выполни `npm ci`.
2. Выполни `npm run local:build`.
3. Запусти `Start-CQA.cmd`. При первом скачивании модели используй `powershell -File .\Start-CQA.ps1 -DownloadModel`.
4. Открой http://127.0.0.1:4173/check.html.

Локальный сервер модели использует порт 11435, проверяющий — 8088, сайт — 4173. Повторный запуск использует уже работающие службы. Для отдельной проверки сборки можно указать `-SitePort 4174 -CheckerPort 8090 -NoBrowser`. Модель работает локально; платный API для оценки не нужен. Не выключай ПК во время оценки.

Данные и все версии решений хранятся в `checker/data/app/cqa.sqlite3`; папка исключена из Git. На другом компьютере начальная база пуста: загрузи свой JSON. Если переносишь существующую базу, делай SQLite backup при остановленных заданиях; не публикуй её в репозитории.

## Правила оценки

По умолчанию `checker/config/checklist.json` содержит рабочий профиль приложения. Оригинальная шкала консультации — 0/5/10/15/20, ведения диалога — 0/4/7/10. Вес критерия применяется отдельно; баллы после N/A нормализуются до 100.

Для сдачи по приложению к гайду используй **`checker/config/checklist.official.json`**: веса 10/15/20/20/15/15/5, оценивается только оператор. Формат результатов находится в `scripts/submission/submission_format.py`. Номера `evidence_turns` начинаются с 1 по полному исходному массиву, включая бота, клиента и системные события. Грубый флаг не обнуляет баллы.

В корне нужны `results/dev/results.json` и `results/prod/results.json`. Ошибки обработки сохраняют ID, `status: "error"`, `criteria: []`, `score: null` и причину. Пользовательские эталоны не выдаются за вывод модели. Подробности готового запуска находятся в `results/README.md`.

## Модель, память и ограничения

Используется Qwen3.5 4B через Ollama, извлечение фактов, проверка цитат и два прохода. Согласие одной модели с собой не доказывает правильность. Оценки предварительные; критичные решения требуют проверки.

В `checker/config/learned_examples.json` находится TF-IDF память синтетических учебных примеров. Веса языковой модели здесь не дообучались. Подготовленный SFT-набор в `training/synthetic-reference` — не подтверждение выполненного fine-tuning. Клиентские эталоны и подтверждённые пользователем апелляции в публичную конфигурацию не включены.

Веб-сайт из корня проекта сохраняет функции текущей ветки GitHub, включая Coach. Облачные функции требуют своей конфигурации и не становятся локальными только от копирования кода. Бесплатный локальный маршрут проверки — `Start-CQA.cmd`; он использует SQLite и локальную модель.

## Проверки

`npm run build`, `npm test`, `npm run check`, `npm run local:build`; из папки `checker`: `python -m unittest discover -s tests`.

SWAP — отдельный дополнительный набор. См. `swap/README.md`. До дополнительной инструкции он не оценивается и не включается в `results/prod`.
