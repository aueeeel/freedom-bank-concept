# Сдача CQA: команда «жи ши пишется через»

Основание: CQA Student Guide v3, Appendix Results JSON 1.0 и выданный PDF чек-листа. В гайдах нет обязательного шаблона имени репозитория. Используется существующий публичный репозиторий [aueeeel/freedom-bank-concept](https://github.com/aueeeel/freedom-bank-concept), чтобы ссылка на решение оставалась постоянной.

## Что сдаётся

| Файл от корня репозитория | Содержимое |
| --- | --- |
| `results/dev/results.json` | Ровно 65 записей: 60 чатов и 5 звонков DEV |
| `results/prod/results.json` | Ровно 10 контрольных чатов; до получения набора это явно обозначенный пустой шаблон |

Одна запись соответствует одному исходному `conversation_id`. Оценивается оператор; бот, клиент и системные события сохраняются как контекст. Аудио не требуется распознавать повторно: используются выданные транскрипты. Этот локальный экспорт не оценивает дикцию или интонацию по звуку.

## Запуск локальной модели

Нужны Node.js 22+, установленный `llama-server` из llama.cpp и файл дообученных весов `Qwen3.5-4B-cqa-Q4_K_M.gguf`. Веса размером около 2,8 ГБ не включены в Git. Обучающие ноутбуки лежат в `training/`; конкретный файл весов команда предоставляет отдельно. Вызовов платного API для этого экспорта нет; расходы на собственное оборудование не включены.

В первом терминале запустите:

```powershell
llama-server -m "D:\models\Qwen3.5-4B-cqa-Q4_K_M.gguf" -c 8192 -t 8 -ngl 0 --device none --host 127.0.0.1 --port 8080 --reasoning-budget 0
```

Путь к весам замените своим. Не открывайте этот порт в интернет. В репозитории не нужны API-ключи для пакетной сдачи. `submission/config.json` содержит название команды и фактически используемую локальную модель. Runner проверяет модель через `/v1/models` и прекращает запуск, если запущены другие веса.

## DEV

Из корня репозитория, во втором терминале:

```powershell
node submission/run.mjs --split dev --input "C:\путь\dev.json" --resume --retry-errors
node submission/validate.mjs --split dev --file results/dev/results.json --input "C:\путь\dev.json"
```

Runner обрабатывает записи последовательно. После каждого диалога сохраняется checkpoint в игнорируемой папке `tmp/submission/`. Повторный запуск с `--resume` продолжает прерванную обработку; `--retry-errors` повторяет только ошибки. Checkpoint привязан к исходному набору, модели и чек-листу. Финальный файл создаётся атомарно после обработки всех записей. Код завершения 2 означает, что файл сформирован, но в нём остались ошибки обработки; они не скрываются.

Если модель не запущена, runner завершится до создания новых результатов. Он не выдаёт недоступность модели за 65 якобы выполненных оценок.

## Контрольный набор PROD

Организаторы выдают доступ через 23 часа после старта; на получение, обработку, проверку и push остаётся 1 час. Получите JSON по их API и сохраните его локально как `prod.json`. Не меняйте ID и исходный порядок реплик.

```powershell
node submission/run.mjs --split prod --input "C:\путь\prod.json" --resume --retry-errors
node submission/validate.mjs --split prod --file results/prod/results.json --input "C:\путь\prod.json"
git add results/dev/results.json results/prod/results.json
git commit -m "Submit DEV and control CQA results"
git push origin main
```

Проверьте оба файла в веб-интерфейсе GitHub. Локального сохранения и commit без push недостаточно. Ссылку на открытый репозиторий команда передаёт организаторам самостоятельно.

Не запускайте контрольный набор впервые в последние минуты: скорость зависит от процессора, длины транскриптов и доступной памяти. Полный прогон DEV помогает заранее измерить время. После стоп-кода код не меняют; обработку данных и изменение чек-листа через уже зафиксированный интерфейс гайд разрешает.

## Контракт результатов

- UTF-8 JSON, `schema_version: "1.0"`, `team_name`, `model`, `results`.
- `model.mode`: `local`, `external_api` или `hybrid`; здесь используется `local`.
- Для `status: "ok"` обязательны все восемь критериев по одному разу, краткое обоснование и непустые номера реплик.
- `evidence_turns` начинается с 1 по полному исходному транскрипту, включая клиента, бота и события. Нумерация не сжимается до реплик оператора.
- Для ошибки сохраняется исходный ID, `status: "error"`, `criteria: []`, `score: null` и непустое поле `error`.
- Ошибки входят в требуемые 65/10 записей. Для дополнительного запрета ошибок при проверке добавьте `--require-success`.

| Код сдачи | Внутренний код сайта | Допустимые значения | Вес |
| --- | --- | --- | --- |
| contact | contact | true / false | 10 |
| discovery | needs | true / false / null | 15 |
| identification | identity | true / false / null | 20 |
| consultation | consultation | 0, 5, 10, 15, 20 / null | 20 |
| empathy | empathy | true / false | 15 |
| dialogue | management | 0, 4, 7, 10 | 15 |
| closure | closing | true / false / null | 5 |
| critical | gross | true / false | отдельный флаг |

`null` означает только разрешённое N/A. Формула: `100 × сумма заработанных баллов / сумма применимых весов`, итог округляется до двух знаков. Шкальный балл сначала делится на максимум шкалы и умножается на вес. `critical_flag` совпадает с `critical.value` и не обнуляет итог.

Веса этого экспорта соответствуют приложенному PDF: **10/15/20/20/15/15/5**. Они задаются в `submission/lib.mjs` отдельно от текущих весов интерфейса **5/20/10/30/15/15/5**. Если организаторы выдадут новые правила сдачи, сначала согласуйте версию: нельзя молча подменять веса или копировать итог с сайта.

Общий экспорт сайта `freedom-cqa-report` / `freedom-cqa-file-results` имеет другой контракт и может содержать отдельные оценки бота. Его нельзя переименовать в `results.json` и считать готовой сдачей.

## Проверки

```powershell
node submission/test.mjs
node --check submission/run.mjs
node --check submission/validate.mjs
```

Валидатор проверяет типы, уникальность критериев и ID, состав исходного набора, диапазон номеров реплик, формулу балла, N/A и отдельный флаг нарушений. Он проверяет формат и арифметику, но не заменяет экспертную проверку смысла оценок модели.

## Защита: 5 минут

1. 1 минута: открыть `/check.html`, показать загруженный диалог.
2. 2 минуты: открыть критерии, обоснование, переход к реплике и пример N/A с итогом.
3. 1 минута: подать апелляцию, показать решение проверяющего и перерасчёт.
4. 1 минута: изменить критерий и применить сохранённый чек-лист.

Для демонстрации без регистрации используйте локальный `npm run dev:model`; при работающей модели он оценивает оператора через локальный маршрут без облачного входа. На опубликованном сайте облачная автоматическая оценка требует менеджера и подключённого обработчика. Профили сотрудников и AI Coach — дополнительные функции, не условие локальной сдачи.
