# Freedom CQA

**Команда «жи ши пишется через» · Freedom Broker CQA Hackathon**

Прототип Conversation Quality Analytics: загрузка разговоров на RU, KZ и EN, оценка оператора по восьми критериям, обоснования со ссылками на реплики, N/A, апелляции и пересчёт итогового балла.

[Открыть проверку](https://freedom-bank-concept.vercel.app/check.html) · [Инструкция по сдаче](docs/hackathon-submission.md) · [Результаты](results/README.md)

## Быстрый запуск

Нужен **Node.js 22 или новее**. Из корня этого репозитория:

```powershell
npm ci
npm run build
npm run dev
```

Откройте [http://127.0.0.1:4173/check.html](http://127.0.0.1:4173/check.html). Для локального просмотра, ручной проверки, изменения чек-листа и демонстрации апелляций регистрация не нужна. На опубликованном сайте автоматическая проверка через облачную очередь требует входа менеджера и работающего внешнего обработчика.

Чтобы оценивать оператора полностью локально, сначала запустите `llama-server` с весами команды, затем вместо `npm run dev` выполните:

```powershell
npm run dev:model
```

[Точная команда запуска модели и требования к весам](docs/hackathon-submission.md#запуск-локальной-модели). Веса модели не входят в Git. Без работающей модели интерфейс остаётся доступен для ручной проверки; автоматическая оценка не подменяется демонстрационными данными.

## Что показать жюри

1. Прикрепить JSON с диалогами, выбрать разговор и открыть транскрипт. Поддерживаются также TXT, CSV, SRT, VTT и текстовый PDF; записи разговоров можно прослушивать.
2. Открыть оценку: ответ по каждому критерию, вес, обоснование и переход к реплике-доказательству.
3. Показать N/A и нормализацию оставшихся весов до 100.
4. Подать апелляцию по критерию, сохранить решение проверяющего и увидеть новый итог. Исходная оценка и решение сохраняются.
5. Изменить формулировку, вес, тип или шкалу критерия через настройки и применить сохранённый чек-лист.

[План защиты на 5 минут](docs/hackathon-submission.md#защита-5-минут). Интерфейс построен на HTML/CSS/JavaScript и React; перенос в Dynamics 365 потребует адаптации, готовый PCF-компонент не заявляется.

## Файлы сдачи

| Набор | Путь | Обязательный состав |
| --- | --- | --- |
| DEV | [results/dev/results.json](results/dev/results.json) | 65 исходных ID: 60 чатов и 5 звонков |
| PROD | [results/prod/results.json](results/prod/results.json) | 10 контрольных чатов, включая ошибки |

**PROD сейчас является пустым шаблоном: контрольный набор ещё не получен.** Это не готовая контрольная сдача. Финальный валидатор отклонит его, пока не появятся все 10 исходных ID.

Для пакетной сдачи используются дообученные локальные веса **Qwen3.5-4B-cqa-Q4_K_M.gguf**, `model.mode = "local"`. Runner не вызывает платный API; стоимость вызовов внешнего сервиса для него равна нулю. Скорость и затраты на оборудование зависят от компьютера. AI Coach использует отдельный сервис и не участвует в этих результатах.

```powershell
node submission/run.mjs --split dev --input "C:\путь\dev.json" --resume --retry-errors
node submission/validate.mjs --split dev --file results/dev/results.json --input "C:\путь\dev.json"

node submission/run.mjs --split prod --input "C:\путь\prod.json" --resume --retry-errors
node submission/validate.mjs --split prod --file results/prod/results.json --input "C:\путь\prod.json"
```

Экспорт сохраняет исходные ID и номера реплик **с 1 по полному транскрипту**, включая бота и системные события. При ошибке запись остаётся в файле с `status: "error"` и `score: null`. Результаты модели предварительные и требуют проверки.

Контракт сдачи JSON 1.0 и веса из приложенного PDF **10/15/20/20/15/15/5** закреплены в `submission/lib.mjs`. Текущие веса интерфейса **5/20/10/30/15/15/5** на пакетный экспорт не влияют. Коды `discovery`, `identification`, `dialogue`, `closure`, `critical` преобразуются из внутренних ID явно. Грубое нарушение отмечается отдельным флагом и автоматически не обнуляет итог.

Через 23 часа после старта организаторы выдают контроль; до стоп-кода нужно получить набор, обработать его, проверить JSON и выполнить **commit и push обоих файлов**. [Пошаговая инструкция](docs/hackathon-submission.md#контрольный-набор-prod).

## Архитектура

- `src/qa-*.ts(x)` — импорт, чек-лист, расчёт, карточки, апелляции и интерфейс.
- `cqa-local-model.cjs` — локальный адаптер к llama-server.
- `api/cqa.mjs`, `lib/cqa-queue.mjs` — закрытая очередь для опубликованного сайта.
- `submission/` — независимый формат сдачи, пакетный runner, валидатор и тесты.
- `results/dev/`, `results/prod/` — только файлы для организаторов.
- `training/` — ноутбуки дообучения.
- `src/workforce-*`, `src/coach-*` — дополнительные профили сотрудников, рейтинги и тренировки.
- `scripts/build.cjs` — сборка сайта в `dist/`.

Секреты, локальные наборы, checkpoint и файл весов не требуется публиковать. В Git не добавляйте `.env*`, токены, пароли и рабочие журналы. Ключи облачных сервисов для локального пакетного экспорта не нужны.

## Проверки

```powershell
node submission/test.mjs
npm test
npm run check
```

Проверки сдачи покрывают типы JSON, все восемь кодов, уникальность и полноту ID, исходные номера реплик, N/A, округление, отдельный `critical_flag` и честные записи ошибок. Это проверка контракта и арифметики, а не независимая метрика качества модели.
