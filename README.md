# Freedom Bank concept · CQA

Статический сайт: главная с вращающейся картой, демонстрационная команда и страница проверки диалогов `/check.html`. Общий шрифт Montserrat, чёрный фон и лаймовые акценты. На главной — предоставленное видео воды; на странице сотрудников — интерактивный Wave Mesh, а CQA использует ровный чёрный фон и белый текст.

## Разработка

- `npm ci` — установка зафиксированных зависимостей.
- `npm run build` — сборка React-компонентов и статических файлов в `dist`.
- `npm run dev` — локальный сервер http://localhost:4173. Другой порт задаётся через `PORT`.
- `npm test` — баллы, N/A, апелляции и импорт транскриптов.
- `npm run check` — проверка синтаксиса JavaScript.

Публикуется только содержимое `dist`. Документы хакатона, тестовые файлы, служебное состояние публикации и переменные окружения туда не входят.

## Проверка диалогов

После загрузки JSON в режиме «Авто» каждый диалог сохраняется отдельно. Для бота и оператора создаются отдельные карточки с оценкой из 100. Таблица файла показывает все карточки; пакетная проверка обрабатывает их последовательно и сохраняет результаты при частичной ошибке. Режим «Один чат» позволяет явно объединить части разговора.

Работают импорт JSON/TXT/CSV/SRT/VTT/текстовых PDF, прослушивание аудио, ручная проверка, автоматическая оценка исходного чек-листа, повторное рассмотрение апелляций, доказательства и экспорт. Автооценка требует входа менеджера и включённого ПК с локальным обработчиком. Скачивайте отчёт для сохранения ручных правок; оценки оператора можно сохранить в профиль сотрудника. Подробности: [CQA-ONLINE.md](CQA-ONLINE.md).

На опубликованном сайте автоматического анализа нет: `qa-config.js` содержит пустые адреса серверных маршрутов, секретов в нём быть не должно. Распознавание речи не подключено. Контракты подключения и ограничения описаны в `CQA-IMPLEMENTATION.md`.

### Автооценка локальной моделью

Дообученная Qwen3.5-4B (Colab-ноутбук `training/train_cqa_colab.ipynb`, 91 % совпадения с эталоном на 26 отложенных диалогах) работает только на этом компьютере:

1. `llama-server -m D:\models\Qwen3.5-4B-cqa-Q4_K_M.gguf -c 4096 -t 8 -ngl 0 --device none --port 8080 --reasoning-budget 0`
2. `npm run dev:model` — локальный сайт с маршрутом `/api/cqa/analyze` (`cqa-local-model.cjs`). Адрес модели можно задать через `CQA_MODEL_URL`.

В «Проверке» появится кнопка «Начать автооценку»; один диалог оценивается около минуты. Оценки модели — черновик: проверяющий подтверждает или правит их перед сохранением. Прослойка подставляет ту же инструкцию, что при обучении, переводит id реплик туда и обратно и отклоняет недопустимые значения.

## Вход и публикация

Регистрация и вход используют отдельный Supabase-проект с email и паролем, без подтверждения адреса. В браузере находится только публичный ключ. Аккаунт относится к дизайн-концепту, а не к интернет-банку.

Сайт: https://freedom-bank-concept.vercel.app/. Сведения о выпуске находятся в `deployment-state.json` и не публикуются. React собирается в самостоятельные бандлы для сотрудников и CQA. При переносе в Dynamics 365 потребуются адаптация путей, хранения и интеграции; это не готовый PCF-компонент.

## Автопубликация из GitHub

Репозиторий `aueeeel/freedom-bank-concept` связан с существующим проектом Vercel `freedom-bank-concept`. Ветка production — `main`. После успешной сборки обновляется https://freedom-bank-concept.vercel.app/. Vercel устанавливает зависимости через `npm ci`, выполняет сборку и проверки, затем публикует только `dist`. Изменения в исходниках React нужно коммитить в `src`; бандлы пересобираются автоматически. Для приватного репозитория на Hobby автор коммита должен иметь право на deployment в проекте Vercel.

## Профили и рейтинги сотрудников

Раздел «Сотрудники» содержит личные профили, историю разговоров, пятизвёздочный рейтинг и апелляции. Руководитель вводит email и отправляет приглашение из формы добавления либо настроек существующего профиля. Новый сотрудник задаёт пароль по ссылке из письма, зарегистрированный открывает свой кабинет. Доступ к своим данным проверяет Supabase RLS. Отправка использует серверную Edge Function и SMTP Supabase. Настройка приглашений и контракт для отдельной серверной части ИИ описаны в `WORKFORCE-INTEGRATION.md`. Учебный пример доступен отдельно без входа.
